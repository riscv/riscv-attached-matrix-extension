[[instructions]]
== Instructions
:imagesdir: ../images
:source-highlighter: rouge




AME defines *141* instructions.

[IMPORTANT]
====
Each instruction is specified by its `Description`, architectural `Operation`,
and the named common contract in <<programming_model>>.  The common rules define
state access, operand validation, complete register-group formation, logical
element access, source snapshots, exception priority, and atomic writeback.

In operation formulas, `A` denotes `ms1`, or the sole M-register source named
`ms` or `ms2` when a mnemonic has no `ms1`; `B` denotes `ms2` in a two-source
form; `D` denotes `md`; and `C` denotes the accumulator operand.  `A_s` and
`B_s` are logical square `s` of A and B.  `c` is a scalar operand.  `D` or `C`
on the right-hand side means the pre-instruction destination value.  Coordinates
`i` and `j` range over the logical square, and `k` is a reduction or matrix-product
index.  Formulas describe all squares and registers selected by the common
operand-formation rules, including packed and wide datatypes.

The pre-instruction RHS rule has one explicit exception for scatter collisions.
Each scatter target is initialized from its pre-instruction `D` value, and a
later contribution to the same target reads the staged result left by the
preceding source element in the instruction-defined update order.
====

[#ame:doc:inst:asettyp]
=== `asettyp`

Synopsis::
Set accumulator datatype

Mnemonic::
`asettyp ad, xs1`

Encoding::
+
[IMPORTANT]
This encoding is provisional and is not a final RISC-V allocation.
+
[wavedrom, ,svg,subs='attributes',width="100%"]
....
{"reg":[{"bits":7,"name": 0x2b,"type":2},{"bits":5,"name": "ad","type":4},{"bits":3,"name": {ame-enc-funct3},"type":2},{"bits":5,"name": "xs1","type":4},{"bits":5,"name": 0x1,"type":2},{"bits":7,"name": {ame-enc-r2-bank0-funct7},"type":2}]}
....

Description::
Sets the datatype of an `Acc` register and clears every physical storage bit of
the accumulator to zero.  This is a raw-bit clear, not conversion to the new
datatype's semantic zero.  The new 32-bit descriptor is `X[xs1][31:0]`; any
upper X-register bits are ignored.

Operation::
+
[source]
----
Ad[ad] = X[xs1][31:0]; raw_bits(Acc[ad]) = 0
----
+
This operation uses the common rules in <<ame-common-datatype-support>>.

Synopsis::
Column unzip (de-interleave columns from two inputs)

Mnemonic::
`mcolunzip.ew md, ms1, ms2`

Encoding::
+
[IMPORTANT]
This encoding is provisional and is not a final RISC-V allocation.
+
[wavedrom, ,svg,subs='attributes',width="100%"]
....
{"reg":[{"bits":7,"name": 0x2b,"type":2},{"bits":5,"name": "md","type":4},{"bits":3,"name": {ame-enc-funct3},"type":2},{"bits":5,"name": "ms1","type":4},{"bits":5,"name": "ms2","type":4},{"bits":7,"name": 0x61,"type":2}]}
....

Description::
De-interleaves the columns of the two-square logical source formed by the
logical source square at `ms1` followed by the logical source square at `ms2`
into the two destination operands `D0` and `D1`.
+
Let `N = sqrt(AME_NELEM)`. For each row `i` and index `j` in `[0, N/2)`:
+
  D0[i, j]         = A[i, 2j]
  D0[i, N/2 + j]   = B[i, 2j]
  D1[i, j]         = A[i, 2j+1]
  D1[i, N/2 + j]   = B[i, 2j+1]
+
where `A` and `B` are the logical source squares at `ms1` and `ms2`.
Even-indexed columns of the logical source are collected into `D0`;
odd-indexed columns into `D1`.  Each source is its sole square.
+
The common datatype size is no smaller than `AME_UNIT_DATATYPE_SIZE`; packed
datatypes are not supported.
+
`D0` is the logical square at `md`, and `D1` occupies the consecutive M
registers immediately following `D0`.  A datatype wider than
`AME_UNIT_DATATYPE_SIZE` therefore spans multiple consecutive M registers per
destination operand.
+
`md` must be aligned to the combined register span of `D0` and `D1`
(even-aligned when each destination operand occupies a single M register).
Inverse of `mcolzip.ew`.

Operation::
+
[source]
----
D0[i,j] = A[i,2j]
D0[i,N/2+j] = B[i,2j]
D1[i,j] = A[i,2j+1]
D1[i,N/2+j] = B[i,2j+1]
----
+
This operation uses the common rules in <<ame-common-structural>>.

+
[source]

D0[i,2j] = A[i,j]
D0[i,2j+1] = B[i,j]
D1[i,2j] = A[i,N/2+j]

=== `mconv.ew`

Synopsis::
Convert element data between supported datatypes, including packed and non-packed representations

Mnemonic::
`mconv.ew md, ms1`

Encoding::
+
[IMPORTANT]
This encoding is provisional and is not a final RISC-V allocation.
+
[wavedrom, ,svg,subs='attributes',width="100%"]
....
{"reg":[{"bits":7,"name": 0x2b,"type":2},{"bits":5,"name": "md","type":4},{"bits":3,"name": {ame-enc-funct3},"type":2},{"bits":5,"name": "ms1","type":4},{"bits":5,"name": 0xd,"type":2},{"bits":7,"name": {ame-enc-r2-bank0-funct7},"type":2}]}
....

Description::
Converts element data between supported datatypes.
+
The source datatype is determined from `Md[ms1]` and the destination datatype from `Md[md]`.
The source and destination datatypes may each be a packed or a non-packed datatype; no
particular packedness combination is required.  Both operands are formed by the common
operand-formation rules, so the instruction's square count is `N_sq = max(pack_factor)`
and every operand spans exactly `N_sq` squares.
+
`mconv.ew` converts each element of the formed logical source operand from the source
datatype to the destination datatype and writes the result squares to the formed logical
destination operand.  A packed source with a non-packed destination therefore expands
the source squares; a non-packed source with a packed destination compresses them; and
operands with the same packedness convert each element without changing the square layout.
+
Element conversion follows the common datatype conversion rules; unsupported conversion tuples set
`amestatus.UN` and do not modify any register.

Operation::
+
[source]
----
D = convert(A) over every element of the formed logical operands
----
+
This operation uses the common rules in <<ame-common-register-groups>>.

=== `mbcast.m.x`

Synopsis::
Convert an X-register scalar and broadcast it to an M operand

Mnemonic::
`mbcast.m.x md, xs1, xtyp`

Encoding::
+
[IMPORTANT]
This encoding is provisional and is not a final RISC-V allocation.
+
[wavedrom, ,svg,subs='attributes',width="100%"]
....
{"reg":[{"bits":7,"name":0x2b,"type":2},{"bits":5,"name":"md","type":4},{"bits":3,"name":{ame-enc-funct3},"type":2},{"bits":5,"name":"xs1","type":4},{"bits":5,"name":"xtyp","type":4},{"bits":7,"name":0x58,"type":2}]}
....

Description::
Interprets the low 32 bits of `X[xtyp]` as an AME datatype encoding and the
X-register bit pattern as one scalar of that datatype, where
`src_dtype = X[xtyp][31:0]`.  If `sizeof(src_dtype)` is less than XLEN, only
the low `sizeof(src_dtype)` bits are used and higher X-register bits are
ignored; if it is greater than XLEN, `X[xs1]` is zero-extended to that width.
The
scalar is converted once to the destination datatype `Md[md]` using the
common scalar conversion rules, then the converted value is written to every
logical element of `M[md]`.  Packed destinations receive the value in every
logical packed element.
+
The source and destination datatype encodings must be supported, and the
source-to-destination conversion must be supported.  Otherwise,
`amestatus.UN` is set and no destination state is modified.  The instruction
does not read `CSR[ame_scalar_dtype]`; the source datatype is its explicit
`xtyp` operand.

Operation::
+
[source]
----
D[i] = convert(X[xs1], source datatype X[xtyp], destination datatype Md[md])
----
+
This operation uses the common rules in <<ame-common-register-groups>>.

=== `fence.ame`

Synopsis::
Order selected AME memory transfers before selected non-AME memory transfers

Mnemonic::
`fence.ame sw, sr, pw, pr`

Encoding::
+
[IMPORTANT]
This encoding is provisional and is not a final RISC-V allocation.
+
[wavedrom, ,svg,subs='attributes',width="100%"]
....
{"reg":[{"bits":7,"name": 0x2b,"type":2},{"bits":1,"name": "sw","type":4},{"bits":1,"name": "sr","type":4},{"bits":1,"name": "pw","type":4},{"bits":1,"name": "pr","type":4},{"bits":1,"name": 0,"type":2},{"bits":3,"name": {ame-enc-funct3},"type":2},{"bits":5,"name": 0x0,"type":2},{"bits":5,"name": 0x2,"type":2},{"bits":7,"name": {ame-enc-r1-bank-funct7},"type":2}]}
....

Description::
Orders AME memory transfers selected by the predecessor bits (`pr`, `pw`) before
non-AME memory transfers selected by the successor bits (`sr`, `sw`):
+
--
* `pr` (bit 10) — predecessor set includes AME loads (reads from memory into `M` registers).
* `pw` (bit 9) — predecessor set includes AME stores (writes from `M` registers to memory).
* `sr` (bit 8) — successor set includes non-AME loads (reads into X, F, or V register files).
* `sw` (bit 7) — successor set includes non-AME stores (writes from X, F, or V register files).
--
+
When all four bits are set (`fence.ame sw, sr, pw, pr`), all AME memory transfers are
guaranteed to be globally visible before any subsequent non-AME memory transfer.
Clearing a bit excludes the corresponding transfer class from the ordering constraint.
At least one of `pr`/`pw` must be set, and at least one of `sr`/`sw` must be set;
otherwise the instruction executes as a NOP with no ordering effect.
+
This instruction is the AME-to-non-AME ordering primitive described in
<<ame-consistency-model>>. It does *not* order non-AME transfers before AME transfers;
for that direction, software must use the standard RISC-V `fence` instruction.
+
`fence.ame` has no source or destination register operands. The four fence bits
are encoded in the `rd` field position (bits 11:7), following the R1 instruction format.

Operation::
+
[source]
----
order AME predecessors selected by pr/pw before non-AME successors selected by sr/sw
----
+
This operation uses the common rules in <<ame-common-ordering>>.
